Design language proposal

Cool room,
warm paper.

A calm system for Notes. The interface around your notes goes quiet and slightly cool; the notes themselves stay warm and hand-dyed. That contrast is the whole idea — the only colour that shouts on screen is colour you chose yourself.

Where it stands

What the audit found

Not a criticism of the build — this is what every app looks like before someone draws a line around it. These are the specific things a design language fixes.

Today

Four grey families in play at once — gray-*, slate-*, a custom dark-* set, and one-off hexes #f5f5f7 / #e0e0e2.

Proposed

One neutral ramp, seven steps, faintly violet so it agrees with the brand instead of fighting it.

Today

Every note card is a fixed 18rem × 16rem. A three-word note gets the same box as a long one, so the board is mostly empty space.

Proposed

Cards size to their content in a masonry column layout, with a max height and a soft fade for long notes.

Today

The editor toolbar is a static strip under the title. Bold, italic, underline only, 32px targets, and it scrolls out of view with the content.

Proposed

A floating pill pinned to the bottom that rides above the keyboard. 44px targets, and room for lists and checkboxes.

Today

Buttons carry focus:outline-hidden with nothing put back — keyboard focus is invisible across the whole app.

Proposed

A single :focus-visible ring token applied at the base layer. This one is an accessibility bug, not a preference.

Today

Poppins loads at weights 400 and 500, but font-bold (700) is used in several places — the browser is faking those bolds.

Proposed

Self-hosted faces at the weights actually used, which also removes a render-blocking Google Fonts import.

Today

Buttons are rounder (12px) than the cards containing them (8px). Two shadow values total, both invisible on the dark background.

Proposed

A five-step radius scale where containers are always rounder than their contents, and elevation that switches from shadow to surface lightness in dark mode.

Why plum and not terracotta. The reference shots lean orange, but the logo, the PWA theme colour and the installed app icon are all #8f5bbd. Moving to terracotta means re-cutting the brand. Note colours

Hand-mixed rather than stock Tailwind *-100, which skew cool and plasticky. Light shades clear 13:1 against ink and dark shades 10:1, so note text is accessible at any size without per-colour overrides.

One rule: a container is never less round than its children. A 12px button inside an 18px card is correct; today's 12px buttons inside 8px cards read as a mistake.

Shadows are tinted with the ink hue rather than pure black — that alone is most of what separates a calm interface from a harsh one. In dark mode shadow barely reads, so elevation switches to progressively lighter surfaces plus a border; the tokens swap, the components don't change.

Foundation 04

Controls

Work Groceries Reading list

Every control is at least 44px tall. Hover shifts background rather than scale — the current hover:scale-105 makes buttons jitter next to each other and does nothing for keyboard users. Press is the only place a spring easing is allowed.

The main proposal

Editing moves to the bottom

On a phone your thumb lives at the bottom of the screen and the keyboard covers the lower third. Today's toolbar is pinned under the title at the top — the furthest possible point from both. Moving it to a floating pill fixes reach, and gives room for the list and checkbox controls the editor is missing.

Foundation 05

Motion

Specified now, built later. The rule that makes motion feel calm rather than busy: things arrive slowly and leave quickly. Only direct manipulation is allowed to overshoot — content never bounces.

Easings

Token Curve Used for
enter cubic-bezier(.22, 1, .36, 1) Anything appearing — sheets, cards, toasts. Long settle reads as calm.
exit cubic-bezier(.4, 0, 1, 1) Anything leaving. Accelerate away; never linger.
move cubic-bezier(.65, 0, .35, 1) Something travelling between two known states — the active pill sliding along the toolbar.
press cubic-bezier(.34, 1.56, .64, 1) Direct manipulation only — button press, FAB. The single place overshoot is allowed.

Choreography

Moment Timing Behaviour
Board load 240ms · enter Cards fade up 8px at scale .98, staggered 30ms in reading order. Caps at 8 cards, then the rest appear together.
Open a note 420ms · enter The card's colour and radius expand into the sheet — the note appears to grow rather than a panel flying in over it.
Close 240ms · exit Reverses, but faster. Asymmetry is the point.
Toolbar mark 240ms · move The filled pill slides between icons instead of two separate fades.
Button press 100ms · press Scale to .94 then settle. Pairs with the existing 50ms haptic.
FAB 360ms · press Icon rotates 90° from plus to close as the sheet opens.
Reorder 240ms · move FLIP on the surviving cards so neighbours slide rather than jump.
Toast 240ms · enter Rises 12px and fades in above the nav pill.
Save 160ms · move Label crossfades to a check, holds 800ms, returns. No spinner for sub-second work.

All of it sits behind prefers-reduced-motion, which the app doesn't honour anywhere today.

Getting there

Adoption path

Ordered so each step is shippable on its own and nothing is a big-bang rewrite.

Land the token layer

Drop the @theme block into app.css alongside the existing tokens. Nothing changes visually yet. Also clears out the corrupt --min-height-* block, the dead @fontsource/fira-mono dependency, and dark:hover:darkHover — a class that has never existed.

Fonts and focus

Self-host Poppins and add Figtree; delete the render-blocking import. Add the :focus-visible ring at the base layer. Smallest diff, biggest accessibility win.

Repaint the primitives

Point lib/button.ts, lib/colours.ts, Input and Note at the new tokens. Swap hover:scale-105 for a background shift. The whole app changes colour in one commit.

Masonry board

Retire the fixed h-note / w-note sizing for CSS columns with a max height and fade. Add the date line and shared chip.

The floating toolbar

Rebuild Toolbar.svelte as the pinned pill, wire it to visualViewport, and add the list, checklist and undo commands. This is the one that needs real device testing.

Motion

Apply the choreography table, guarded by prefers-reduced-motion. Last, because it's the layer that most needs the rest to be settled first.

Proposal for review — nothing here is wired into the app yet. Tokens are in docs/design-system/tokens.css, written against Tailwind v4 theme namespaces so each one becomes a utility class on adoption. The written rules live alongside it in docs/design-system/README.md.
